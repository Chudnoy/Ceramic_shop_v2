# Ceramic Shop v2

Сайт-портфолио и небольшая витрина керамических работ художницы Полины Яланской.

Проект построен на Flask и SQLite. Основной акцент сделан на презентации художественной практики: каталог, страницы отдельных работ, тематические теги и проекты. Коммерческая часть остаётся вторичной и включает корзину, оформление заказа и административную панель.

## Возможности

### Публичная часть

- главная страница и каталог работ;
- поиск, сортировка и фильтрация по категориям;
- фильтрация работ по смысловым тегам;
- отдельная страница работы с описанием, материалами, годом, статусом и тегами;
- отзывы;
- корзина на основе Flask session;
- повторная проверка доступности работ перед оформлением;
- оформление заказа и страница подтверждения;
- адаптивная вёрстка для компьютеров и мобильных устройств.

### Административная часть

- вход по логину и паролю;
- создание, редактирование и удаление работ;
- управление категориями;
- CRUD тегов;
- связь работ и тегов «многие ко многим»;
- управление заказами и их статусами;
- загрузка изображений;
- поиск, фильтрация и сортировка данных.

### Безопасность и валидация

- CSRF-защита POST-форм;
- хешированный пароль администратора;
- серверная валидация форм;
- проверка доступности работы перед добавлением в корзину и оформлением заказа;
- разделение публичных и административных маршрутов.

## Установка

### 1. Клонировать репозиторий

```bash
git clone <URL-РЕПОЗИТОРИЯ>
cd Ceramic_shop_v2
```

### 2. Создать виртуальное окружение

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Windows Command Prompt:

```cmd
python -m venv .venv
.venv\Scripts\activate
```

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Настройка переменных окружения

Создайте в корне проекта файл `.env`:

```env
SECRET_KEY=замените-на-длинную-случайную-строку
ADMIN_LOGIN=admin
ADMIN_PASSWORD_HASH=вставьте-хеш-пароля
```

### Генерация `SECRET_KEY`

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

### Генерация хеша пароля администратора

```bash
python -c "from werkzeug.security import generate_password_hash; print(generate_password_hash('ВАШ_ПАРОЛЬ'))"
```

Скопируйте полученное значение целиком в `ADMIN_PASSWORD_HASH`.

Файл `.env` содержит секреты и не должен попадать в Git.

## Запуск

```bash
python app.py
```

После запуска сайт будет доступен по адресу:

```text
http://127.0.0.1:8000
```

Страница входа в админку:

```text
http://127.0.0.1:8000/admin/login
```

При первом запуске приложение создаёт необходимые таблицы SQLite и добавляет стартовые данные, если соответствующие таблицы пусты.

## База данных

Проект использует SQLite. Основные таблицы:

- `categories` — категории работ;
- `products` — художественные работы;
- `tags` — смысловые теги;
- `product_tags` — связи работ и тегов «многие ко многим»;
- `reviews` — отзывы;
- `orders` — заказы.

В публичной части показываются только работы с `is_visible = 1`.

Работа может быть добавлена в заказ только при одновременном выполнении условий:

```text
is_visible = 1
is_for_sale = 1
status = available
```

## Статусы

### Работы

- `available` — доступна;
- `reserved` — зарезервирована;
- `sold` — продана.

### Заказы

- `new` — новый;
- `processing` — в обработке;
- `completed` — завершён;
- `cancelled` — отменён.

## Разработка

Проект создаётся как учебное Flask-приложение без ORM. SQL-запросы, связи между таблицами, обработка форм, CSRF-защита и валидация реализуются вручную, чтобы сохранить прозрачность архитектуры и лучше понять работу веб-приложения.

Перед коммитом рекомендуется проверить:

```bash
python -m compileall .
```

Также стоит пройти основной пользовательский сценарий:

```text
каталог → страница работы → корзина → оформление → подтверждение
```

## Важные замечания

- Не публикуйте `.env`.
- Не добавляйте в открытый репозиторий рабочую базу с реальными заказами и персональными данными.
- Не используйте стандартный `SECRET_KEY` на размещённом сайте.
- Режим `debug=True` предназначен только для локальной разработки.
- Загруженные изображения хранятся в `static/uploads/`.
