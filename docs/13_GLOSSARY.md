# Глоссарий

## Application factory

Функция, создающая и настраивающая Flask-приложение. В проекте — `create_app()`.

## Blueprint

Группа связанных Flask-маршрутов. Проект использует публичный и административный blueprints.

## Route

Функция, обрабатывающая HTTP-запрос и возвращающая response/redirect/template.

## Service

Слой бизнес-сценариев: валидация, правила, транзакции и координация нескольких операций.

## Database module

Модуль с узкими SQL-функциями.

## Инвариант

Свойство, которое должно оставаться истинным. Например: «работа активного заказа имеет статус reserved».

## Транзакция

Группа SQL-операций, завершаемая целиком через `COMMIT` или отменяемая через `ROLLBACK`.

## Atomicity

Принцип «всё или ничего» для транзакции.

## Race condition

Ошибка, зависящая от порядка параллельных действий. Условный UPDATE уменьшает риск одновременного резервирования.

## `rowcount`

Количество строк, изменённых SQL-запросом. Используется для определения успешности ожидаемого перехода.

## Foreign key

Ограничение связи между таблицами.

## `ON DELETE CASCADE`

При удалении родителя автоматически удаляются зависимые строки. Пример: позиции удалённого заказа.

## `ON DELETE SET NULL`

При удалении родителя ссылка очищается, а зависимая строка остаётся. Пример: историческая позиция после удаления работы.

## Normalization

Разделение данных по связанным таблицам. `order_items` заменили JSON внутри `orders`.

## Historical snapshot

Сохранённые на момент события данные. Название и цена в заказе не меняются вместе с текущей работой.

## Migration

Версионированное преобразование схемы или данных.

## Migration runner

Код, который определяет неприменённые версии и запускает их по порядку.

## Migration registry

`MIGRATIONS` — список объектов с version, name и apply.

## Seed

Начальные демонстрационные или справочные данные. Seed не является описанием схемы.

## Idempotency

Повторный вызов приводит к тому же состоянию. `init_db()` не дублирует применённые миграции и полный seed.

## CSRF

Атака, при которой браузер авторизованного пользователя заставляют отправить нежелательный запрос. Token подтверждает, что POST сформирован приложением.

## Session

Подписанное браузерное состояние Flask. Используется для админского флага, корзины и CSRF token.

## Password hash

Необратимое представление пароля для проверки без хранения открытого значения.

## Compensating action

Действие, вручную отменяющее изменение вне транзакционной системы. Например, удаление нового изображения после rollback БД.

## CI

Continuous Integration: автоматический запуск проверок после push/PR. В проекте — GitHub Actions + pytest.

## Linter

Инструмент статической проверки кода. Планируется Ruff.

## Formatter

Инструмент единого оформления кода. Ruff также умеет форматировать.

## Coverage

Доля строк/ветвей, выполненных тестами. Планируется отчёт pytest-cov.

## Smoke test

Короткая ручная проверка, что ключевые сценарии запускаются после изменений.

## WSGI server

Production-сервер Python web-приложений. Flask development server им не заменяется.

## Reverse proxy

Сервер перед приложением, обычно завершающий HTTPS и перенаправляющий запросы.

## Staging

Среда, похожая на production, но не обслуживающая реальных покупателей.

## Backup / restore rehearsal

Не просто создание копии, а проверка, что её действительно можно восстановить.

## Project / Work / Shop item

Будущие предметные понятия:

- Project — художественный контекст;
- Work — произведение;
- Shop item — коммерческое предложение.

Они ещё не реализованы как отдельные таблицы.
