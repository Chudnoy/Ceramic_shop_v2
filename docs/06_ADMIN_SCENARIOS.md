# Административные сценарии

## 1. Авторизация

### Вход

`GET/POST /admin/login`.

При POST:

1. читается логин;
2. читается пароль;
3. логин сравнивается с `ADMIN_LOGIN`;
4. пароль проверяется `check_password_hash`;
5. в session сохраняется `is_admin = True`;
6. session становится постоянной на один день.

### Защита маршрутов

`admin_bp.before_request` разрешает без авторизации только endpoint логина. Остальные admin endpoints требуют `session["is_admin"]`.

### Выход

`POST /admin/logout` удаляет флаг из session.

## 2. Dashboard

`GET /admin` показывает:

- количество работ;
- количество заказов;
- новые заказы;
- подтверждённые заказы;
- сумму выполненных заказов;
- сумму всех заказов.

## 3. Список работ

`GET /admin/products` поддерживает:

- category;
- status;
- search;
- sorting;
- скрытые работы;
- исключение архива.

Отдельный route показывает архив.

## 4. Создание работы

```text
GET form
POST form
→ process_product_form
→ process_product_tag_ids
→ save_image
→ INSERT product
→ replace_product_tags
→ COMMIT
```

Проверяется:

- обязательность названия, описания и материалов;
- положительная цена;
- год 1990–2100;
- существующая категория;
- разрешённый статус;
- существующие tag IDs;
- запрет `is_featured=1` при скрытой работе;
- расширение изображения.

## 5. Редактирование работы

Полное редактирование проверяет активный заказ.

Когда работа связана с заказом `new` или `confirmed`, её статус обязан оставаться `reserved`. Остальные текстовые поля и теги текущий код позволяет менять.

Изображение:

- новый файл необязателен;
- при отсутствии нового сохраняется старый путь;
- новый файл удаляется при rollback;
- старый файл удаляется после commit.

## 6. Быстрое изменение состояния

`POST /admin/products/state/<id>` изменяет:

- `status`;
- `is_visible`;
- `is_for_sale`;
- `is_featured`.

Проверки активного заказа и featured/visibility действуют так же, как при полной форме.

## 7. Архив

### Перемещение

Разрешено, когда:

- работа существует;
- ещё не архивирована;
- не связана с активным заказом.

### Восстановление

Меняет `is_archived` обратно на `0`.

### Окончательное удаление

Route требует предварительного архива. Service дополнительно запрещает удаление при active order.

После commit удаляется только файл из `/static/uploads/`. Статические seed-изображения из `/static/img/` защищены условием в `delete_image`.

## 8. Категории

Администратор может:

- создать категорию;
- изменить название, slug и описание;
- удалить пустую категорию.

Slug:

- приводится к нижнему регистру;
- допускает латинские буквы, цифры и дефис;
- должен быть уникальным.

## 9. Теги

Администратор может:

- создать тег;
- изменить имя и slug;
- открыть список связанных работ;
- удалить неиспользуемый тег.

И имя, и slug проверяются на уникальность на уровне route; база также имеет UNIQUE-ограничения.

## 10. Заказы

### Список и поиск

Поддерживаются поиск и фильтр по статусу.

### Карточка

Показывает `orders` и связанные `order_items`.

### Редактирование

Разрешено только для `new`.

Можно изменить:

- контактные данные;
- количество существующих позиций.

Цена позиции берётся из сохранённого `unit_price`, а total пересчитывается на сервере.

### Подтверждение

```text
new → confirmed
```

### Выполнение

```text
order: confirmed → completed
products: reserved → sold
```

Одна транзакция охватывает заказ и все связанные работы.

### Отмена

```text
order: new|confirmed → canceled
products: reserved → available
```

### Удаление

Разрешено только для `canceled`. Позиции удаляются каскадно по FK.

## 11. Административные ограничения

Текущая админка рассчитана на одного доверенного администратора. Пока отсутствуют:

- пользователи и роли;
- журнал действий;
- восстановление пароля;
- 2FA;
- rate limiting;
- защита от параллельного редактирования одной формы;
- отдельный workflow публикации черновиков.
