# 4. Работы и их состояния

## Независимые характеристики

### `status`

```text
available — доступна
reserved  — зарезервирована активным заказом
sold      — продана
```

### `is_visible`

Показывается ли работа публично.

### `is_for_sale`

Предлагается ли работа к покупке.

### `is_archived`

Находится ли работа в административном архиве.

### `is_featured`

Выбрана ли работа для акцентного показа.

## Доступность для заказа

Работа может попасть в заказ, только если:

```text
существует в базе
is_archived == 0
is_visible == 1
is_for_sale == 1
status == "available"
```

Причина недоступности централизована в сервисе, чтобы корзина, checkout и карточка не имели разных правил.

## Полное редактирование

`update_product_with_tags()` объединяет:

- проверку активного заказа;
- сохранение нового изображения;
- обновление `products`;
- замену тегов;
- commit/rollback;
- удаление старого или нового файла в правильный момент.

Если работа связана с активным заказом, её нельзя вывести из `reserved`.

```text
активный заказ + новый status != reserved
→ отказ до save_image
```

## Быстрое изменение состояния

Отдельный сценарий меняет `status`, `is_visible`, `is_for_sale`, `is_featured` и также проверяет активный заказ.

## Создание

```text
сохранить изображение
INSERT products
INSERT product_tags
COMMIT
```

Если теги падают:

```text
ROLLBACK базы
удалить новое изображение
raise
```

## Удаление

На уровне route окончательное удаление разрешено только после архива. Сервис запрещает удаление работы с активным заказом.

После успешного удаления базы удаляется изображение. Если файл не удалился, база не откатывается, а администратор получает предупреждение.

```text
лишний файл безопаснее,
чем база, указывающая на отсутствующий файл
```

## Нерешённый вопрос количества

Статусная модель выглядит как модель уникальной работы, но корзина допускает `quantity > 1`.

Нужно выбрать:

### Только уникальные работы

```text
quantity всегда 1
```

### Уникальные и тиражные позиции

Потребуются `sale_type`, `stock_quantity` и атомарное резервирование количества.
