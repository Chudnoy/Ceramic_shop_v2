# 5. Категории, теги и архив

## Категории

Категория — основная классификация:

```text
products.category_id → categories.id
```

Она содержит имя, уникальный slug и описание.

Удаление категории запрещается, пока к ней привязаны работы. Database-функция должна возвращать `True` только если строка действительно удалена, поэтому используется `cursor.rowcount > 0`.

## Теги

Теги — смысловая неиерархическая классификация:

```text
Дом
Память
Архитектура
Разрушение
Хрупкость
Природа
```

Одна работа может иметь много тегов, один тег — много работ.

## Обработка `tag_ids`

Checkbox отправляет строки:

```python
["1", "3", "5"]
```

Сервис:

1. вызывает `form.getlist("tag_ids")`;
2. преобразует значения в `int`;
3. получает существующие ID;
4. проверяет, что все переданные ID существуют;
5. возвращает очищенный список.

Пустой список тегов допустим.

## Замена тегов

Текущая стратегия:

```text
DELETE старые связи
INSERT выбранные связи
```

Обе части обязаны находиться в одной транзакции, иначе ошибка посередине оставит частичный набор.

## Архив

Архив — промежуточное состояние перед окончательным удалением:

```text
основной список → архив → физическое удаление
```

## Архив и скрытие — не одно и то же

```text
is_visible = 0
→ работа остаётся активной в админке, но скрыта публично

is_archived = 1
→ работа переносится из основного административного списка в архив
```

Стоит отдельно формализовать, можно ли архивировать работу с активным заказом.
