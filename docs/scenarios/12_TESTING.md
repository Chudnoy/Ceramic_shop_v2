# 12. Тестирование

## Уровни

### Простая логика

- обработка форм;
- checkbox;
- статусы;
- ID тегов;
- позиции заказа;
- session-корзина.

### Database

- CRUD;
- фильтрация;
- связи;
- `rowcount`;
- внешние ключи;
- CASCADE и SET NULL;
- поиск активного заказа.

### Service

- транзакционный успех;
- rollback;
- сохранение старого состояния;
- компенсация изображения;
- резервирование, освобождение и продажа;
- недопустимые переходы.

### Route

- авторизация;
- CSRF;
- checkout;
- частичный заказ;
- сохранение корзины при ошибке;
- удаление только заказанных позиций.

## Временная база

Типичная fixture создаёт SQLite-файл в `tmp_path`, включает `row_factory` и `PRAGMA foreign_keys = ON`, а затем через `monkeypatch` подменяет подключение сервиса.

## `monkeypatch`

Подмена используется для тестового соединения, `save_image`, `delete_image` и искусственной ошибки на определённом шаге.

Подменять нужно имя в модуле, где оно используется.

## Аварийные тесты

Сильный тест создаёт ошибку после частичного выполнения:

```text
заказ вставлен
первая позиция вставлена
вторая позиция падает
```

После этого проверяется, что обе таблицы пусты. Так доказывается rollback.
