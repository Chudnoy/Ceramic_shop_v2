# Сценарий: редактирование заказа администратором

## Цель

Администратор может исправить данные покупателя или изменить состав существующего заказа, не нарушая резервирование товаров и целостность данных.

## Участники

* **Администратор** — редактирует заказ через административную панель.
* **Система** — проверяет изменения, пересчитывает сумму заказа и синхронизирует состояние товаров.

## Предусловия

* Администратор авторизован.
* Заказ существует.
* Заказ имеет статус `new` или `confirmed`.
* Товары, уже входящие в заказ, зарезервированы за этим заказом.
* Заказы со статусами `completed` и `canceled` недоступны для редактирования.

## Основной сценарий

1. Администратор открывает страницу заказа.

2. Система показывает:

   * идентификатор заказа;
   * дату создания;
   * текущий статус;
   * имя, email, телефон и адрес покупателя;
   * состав заказа;
   * цену каждой позиции;
   * итоговую сумму.

3. Администратор нажимает кнопку «Редактировать».

4. Система открывает форму с текущими данными заказа.

5. Администратор изменяет одно или несколько значений:

   * имя покупателя;
   * email;
   * телефон;
   * адрес;
   * состав заказа.

6. Администратор нажимает кнопку «Сохранить».

7. Система повторно получает заказ из базы данных и проверяет, что:

   * заказ по-прежнему существует;
   * заказ не был выполнен или отменён;
   * передан корректный CSRF-токен;
   * обязательные поля заполнены;
   * email имеет допустимый формат;
   * заказ после редактирования содержит хотя бы одну позицию;
   * указанные товары существуют;
   * добавляемые товары доступны для резервирования;
   * количество каждой позиции допустимо.

8. Система сравнивает новый состав заказа со старым:

   * позиции без изменений сохраняются;
   * добавленные позиции резервируются;
   * удалённые позиции освобождаются от резерва;
   * изменения количества проверяются с учётом доступного остатка.

9. Система пересчитывает итоговую сумму заказа на сервере.

10. Все изменения выполняются в одной транзакции:

    * обновляются данные покупателя;
    * обновляется состав заказа;
    * обновляется итоговая сумма;
    * резервируются добавленные товары;
    * освобождаются удалённые товары.

11. Если все операции выполнены успешно, система фиксирует транзакцию.

12. Администратор возвращается на страницу заказа и видит сообщение:

> Заказ обновлён.

## Правила изменения состава заказа

### Добавление товара

Товар можно добавить в заказ только в том случае, если он доступен.

После добавления:

* создаётся новая позиция заказа;
* в позиции сохраняются название и цена товара на момент добавления;
* товар переводится в состояние `reserved`;
* резерв связывается с редактируемым заказом.

Проверка доступности выполняется непосредственно перед сохранением, а не только при открытии формы.

### Удаление товара

При удалении позиции из заказа:

* позиция удаляется из состава заказа;
* связанный с ней товар освобождается от резерва;
* товар снова получает состояние `available`, если он не зарезервирован другим допустимым процессом.

Нельзя удалить последнюю позицию заказа. Пустой заказ должен быть отменён, а не сохранён без товаров.

### Изменение количества

Для уникальных керамических работ допустимое количество равно `1`.

Если в будущем в каталоге появятся тиражные товары, количество можно будет изменять при условии наличия достаточного остатка.

Количество должно быть целым положительным числом.

## Правила расчёта стоимости

Итоговая сумма никогда не принимается из формы администратора.

Она рассчитывается системой:

```text
итоговая сумма = сумма(цена позиции × количество)
```

Для уже существующей позиции используется цена, сохранённая в `order_items` при оформлении заказа.

Изменение текущей цены товара в каталоге не должно задним числом изменять стоимость уже оформленного заказа.

Для нового товара, добавленного при редактировании, в позицию заказа записывается его актуальная цена на момент добавления.

## Альтернативные сценарии

### Заказ не найден

Если заказ был удалён или передан неизвестный идентификатор:

* изменения не выполняются;
* администратор перенаправляется к списку заказов;
* система показывает сообщение:

> Заказ не найден.

### Заказ уже выполнен или отменён

Если заказ имеет статус `completed` или `canceled`:

* система запрещает сохранение;
* состав заказа и данные покупателя не изменяются;
* система показывает сообщение:

> Выполненный или отменённый заказ нельзя редактировать.

### Некорректные данные покупателя

Если обязательное поле не заполнено или email некорректен:

* изменения не сохраняются;
* система показывает конкретную ошибку;
* администратор остаётся на форме редактирования.

### Добавляемый товар недоступен

Если товар был продан, зарезервирован или скрыт из продажи:

* заказ не изменяется;
* остальные изменения также не сохраняются;
* система показывает сообщение с названием недоступного товара:

> Работа «Название работы» больше недоступна.

Администратор должен обновить страницу и скорректировать состав заказа.

### Попытка сохранить пустой заказ

Если администратор удалил все позиции:

* изменения не сохраняются;
* система показывает сообщение:

> Заказ должен содержать хотя бы одну позицию.

Для прекращения работы с таким заказом используется отдельная операция отмены.

### Ошибка во время сохранения

Если обновление заказа, его позиций или резервов завершается ошибкой:

* транзакция откатывается полностью;
* данные покупателя не изменяются;
* старый состав заказа сохраняется;
* состояния товаров сохраняются в исходном виде;
* система показывает сообщение:

> Не удалось обновить заказ. Изменения не сохранены.

## Постусловия

### При успешном редактировании

* данные покупателя обновлены;
* заказ содержит актуальный состав позиций;
* итоговая сумма пересчитана;
* каждый товар из заказа зарезервирован;
* удалённые из заказа товары освобождены;
* частично применённых изменений нет.

### При ошибке

* заказ остаётся в прежнем состоянии;
* состав заказа не изменяется;
* итоговая сумма не изменяется;
* резервирование товаров не изменяется.

## Что не входит в этот сценарий

Обычное редактирование заказа не включает:

* выполнение заказа;
* отмену заказа;
* восстановление отменённого заказа;
* удаление заказа;
* изменение цены существующей позиции вручную.

Смена статуса оформляется отдельным сценарием, поскольку она имеет самостоятельные бизнес-последствия:

* отмена заказа освобождает зарезервированные товары;
* выполнение заказа переводит товары в состояние `sold`.
