## Критично: инвертированная проверка partial checkout

Сейчас:

```python
if (
    cart_summary["has_unavailable_items"]
    and not request.form.get("confirm_partial_order") != "1"
):
```

`not value != "1"` равносильно `value == "1"`, поэтому поведение инвертировано.

Исправление:

```python
confirmation = request.form.get("confirm_partial_order")

if cart_summary["has_unavailable_items"] and confirmation != "1":
    flash("Подтвердите оформление заказа только из доступных работ", "info")
    return redirect(url_for("main.checkout_form"))
```

После исправления запустить весь pytest.

## Мёртвая функция с ошибкой SQL

В `database/order_items.py` есть `get_products_by_order_id()` с лишней запятой:

```sql
WHERE oi.order_id = ?,
```

Функция импортируется, но не используется. Лучше удалить функцию и импорт, а вернуть только при появлении реального сценария и теста.

## Нет миграций

`ensure_product_columns()` добавляет отдельные столбцы `products`, но не умеет версионировать схему, менять ограничения, перестраивать таблицы и мигрировать заказы.

## Неопределённое количество

Корзина допускает `quantity > 1`, а статус работы единственный. Нужно решить: только уникальные работы, складские позиции или оба типа.

## Order success и персональные данные
