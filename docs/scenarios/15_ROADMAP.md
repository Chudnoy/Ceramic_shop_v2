# 15. Рекомендуемая дорожная карта

## Этап 1. Стабилизация

1. Исправить partial checkout.
2. Удалить мёртвый SQL-код.
3. Запустить все тесты.
4. Добавить тест удалённого ID в корзине.
5. Проверить архивирование с активным заказом.
6. Обновить README и PROJECT_MAP.

## Этап 2. Автоматическая проверка

1. `requirements-dev.txt`.
2. GitHub Actions.
3. pytest на push и pull request.
4. Позже — `ruff`.

## Этап 3. Фабрика приложения

1. `create_app(test_config=None)`.
2. Настройки через `app.config`.
3. Путь базы через конфигурацию.
4. Независимость тестов от локального `.env`.
5. Вертикальные интеграционные тесты.

## Этап 4. Миграции

1. Таблица `schema_migrations`.
2. Последовательные SQL-файлы.
3. Перенос текущей схемы в версии.
4. Индексы.
5. Отказ от случайных `ALTER TABLE` в runtime-коде.

## Этап 5. Модель продажи

### Только уникальные работы

- quantity = 1;
- запрет увеличения;
- серверная проверка.

### Уникальные и тиражные

- `sale_type`;
- `stock_quantity`;
- атомарное резервирование количества.

## Этап 6. Production

- защита order_success;
- отключение debug;
- WSGI;
- логирование;
- резервное копирование;
- лимит загрузок;
- privacy-текст;
- очистка персональных данных.

## Этап 7. Портфолио

После стабилизации ядра:

```text
projects
works
project_works
work_images
exhibitions
texts
```

Особенно естественно отделить проект/серию от отдельной работы и добавить несколько изображений.

## Пока не требуется

- микросервисы;
- React ради React;
- REST API без необходимости;
- сложные роли;
- ORM только ради смены технологии;
- онлайн-оплата до стабилизации бизнес-процесса.
